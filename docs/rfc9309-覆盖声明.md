# robots.txt 处理：RFC 9309 覆盖声明

本文逐条列出 MoonCrawl 对 [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)
（Robots Exclusion Protocol，2022-09）的覆盖情况。目的是把「遵守 robots 协议」
这句承诺**收敛到可核查的范围**，而不是用「实用子集」一笔带过。

- 规范版本：RFC 9309
- 实现位置：`robots.mbt`（解析与匹配）、`crawl.mbt`（状态码与调度语义）
- 验证方式：`moon test --target js -f "robots*"` 与 `-f "crawl*"`
- 声明日期：2026-10-28（2026-11-07 按当前实现重写）

## 0. 记号

- **实现**：行为与条款字面一致，有测试钉住。
- **偏离**：行为与条款字面不同，但理由明确、影响可观测，单列说明。
- **未实现**：不做承诺，使用方需自行承担。

## 1. 逐条覆盖表

| 条款 | 要求 | 级别 | 本项目 | 验证用例 |
| --- | --- | --- | --- | --- |
| §2.2.1 组选择 | product token 大小写不敏感匹配 | MUST | **实现**：UA 与 `User-agent` 值均小写后前缀匹配 | `robots: 注释、空行与大小写` |
| §2.2.1 组选择 | 多个组匹配同一 product token 时合并 | MUST | **偏离**：同名 UA 分散在多组时合并；不同长度的 token 同时匹配时**只取最长的一个**，不合并（见 §1.1） | `robots: 同一 UA 分散在多个组时规则合并`、`robots: 组选择取最长 UA 前缀` |
| §2.2.1 回退 | 无匹配组时遵守 `*` 组 | MUST | **实现**：无具体匹配时合并全部 `*` 组 | `robots: 组选择取最长 UA 前缀` |
| §2.2.1 无规则 | 无匹配组且无 `*` 组 → 无规则适用 | MUST | **实现**：允许一切 | `robots: 无匹配组时允许一切` |
| §2.2.2 匹配起点 | 从 path 第一个字节开始匹配 | MUST | **实现**：严格前缀匹配，模式不得命中路径中段 | `robots: 基本组与 Disallow`、`regression: Allow 规则不得匹配路径中段` |
| §2.2.2 最具体优先 | 采用 octets 最多的匹配规则 | MUST | **实现**：按模式长度取最大（长度以字符计，非 ASCII 场景下与 octet 数不同，但不影响「谁更长」的判定） | `robots: Allow/Disallow 同时命中取更长模式` |
| §2.2.2 等长并列 | Allow 与 Disallow 等价时优先 Allow | SHOULD | **实现**：等长时 Allow 胜出（比「等价」更宽松，与主流实现一致） | `robots: Allow/Disallow 同时命中取更长模式` |
| §2.2.2 空规则 | 组内无匹配规则 → 允许 | MUST | **实现** | `robots: 空值 Disallow 为无操作` |
| §2.2.2 隐式允许 | `/robots.txt` 本身隐式允许 | MUST | **实现**：`is_robots_txt_path` 短路 | `robots: /robots.txt 隐式允许` |
| §2.2.2 裸规则 | 不属于任何组的规则 SHOULD 被忽略 | SHOULD | **实现**：文件开头、任何 `user-agent` 之前的规则直接丢弃 | `robots: 不属于任何组的裸规则被忽略` |
| §2.2.3 注释 | `#` 起行内注释 | MUST | **实现**：解析前截断 | `robots: 注释、空行与大小写` |
| §2.2.3 `*` | 匹配任意字符序列（含空） | MUST | **实现**：线性双指针匹配，无指数回溯 | `robots: 通配符 * 与结尾 $`、`robots: 通配符模式不产生指数回溯` |
| §2.2.3 `$` | 锚定模式结尾 | MUST | **实现** | `robots: 通配符 * 与结尾 $` |
| §2.2.2 百分号（解码向） | 比较前解码 unreserved 字符的 `%XX` | MUST | **实现**：规则与请求两侧都过 `normalize_compare_form` | `robots: 百分号编码的 unreserved 字符参与比较` |
| §2.2.2 百分号（编码向） | 非 ASCII 与保留字符比较前百分号编码 | MUST | **部分实现**：非 ASCII 字符按 UTF-8 编码成 `%XX`，十六进制位统一大写；**ASCII 保留字符不做编码**（见 §1.2） | `robots: 非 ASCII 路径两侧编码形式一致` |
| §2.5 解析上限 | 解析限额 MUST ≥ 500 KiB | MUST | **实现**：上限 1 MiB（`ROBOTS_MAX_CHARS`），超出截断，截断点前的规则照常生效。该上限只约束解析，不约束下载 | `robots: 超过 1 MiB 的解析上限后截断` |
| §2.3.1.1 成功 | 成功下载则执行可解析规则 | MUST | **实现** | `crawl: 假站点端到端——深度与统计` |
| §2.3.1.3 4xx | unavailable → 可访问任意资源 | MAY | **实现**：视为无规则并放行 | `crawl: robots.txt 返回 4xx 视为无规则并放行` |
| §2.3.1.4 5xx / 网络错误 | unreachable → **必须**假定完全禁止 | MUST | **实现**：默认 `RobotsUnreachable::Disallow`，`Allow` 需显式选择 | `crawl: robots 不可达时默认全禁`、`crawl: robots.txt 返回 5xx` |
| §2.3.1.5 解析错误 | 逐行尽力解析，执行可解析部分 | MUST | **实现**：无法识别的行忽略，其余照常 | `robots: 无匹配组时允许一切` 等 |

## 1.1 偏离说明：组选择采用「最长 token 优先」

RFC 9309 §2.2.1 的字面要求是：

> If there is more than one group matching the user-agent, the matching
> groups' rules MUST be combined into one group and parsed according to
> Section 2.2.2.

RFC 定义的是「匹配 / 不匹配」，没有「谁更匹配」。本项目按**最长 product
token 前缀**筛选：只有长度等于最长匹配的那批组会被合并，更短的组被丢弃。

**可观测差异**（`robots: 组选择取最长 UA 前缀` 与本次新增用例覆盖）：

```
User-agent: MoonCrawl        # 组 A：禁 /a
Disallow: /a

User-agent: MoonCrawl/0.1    # 组 B：禁 /b
Disallow: /b
```

UA 为 `MoonCrawl/0.1` 时：

- RFC 字面：两组的规则合并 → `/a` 与 `/b` 都被禁。
- 本项目：只取组 B（token 更长）→ `/a` 被**放行**。

**选择这个偏离的理由**：

1. 与 Google 等主流实现一致（Google 搜索中心文档明确「most specific user-agent
   match takes precedence」），站长写具体 UA 组的意图通常是「覆盖而非追加」；
2. 采用字面合并会让「给某个具体爬虫开白」无法实现——通用组禁了全站，
   具体组也禁，站长没有表达「例外」的手段。

**代价**：如果站长按 RFC 字面理解、期望两组合并，更具体的组会意外放宽权限。
因此本节必须和实现一起读，不能只引用 §1 的「实现」列。

## 1.2 偏离说明：百分号只做了一半

RFC 9309 §2.2.2 有两句相反的转换要求：

1. 「URI 与 robots 路径中，超出 ASCII 范围以及落在 RFC 3986 保留区间的
   octets，比较前 MUST 百分号编码」；
2. 「URI 中出现的百分号编码 ASCII octet，比较前 MUST 解码，除非它是保留
   字符或落在 unreserved 范围之外」。

第 2 句（解码向）**已完整实现**：`%7E` 与 `~` 同路径、`%2F` 与 `/` 不同路径、
非法转义原样保留。

第 1 句（编码向）**只实现了非 ASCII 部分**：`/café` 会被编码成
`/caf%C3%A9` 再比较，因此规则写原文或写编码都能命中。ASCII 保留字符
（`*`、`$`、`,`、`;` 等）**不做编码**。

不做的原因是兼容性：现实中大量 robots 规则直接写未编码的 `,`、`;`，
若把请求路径里的对应字符也编码，这些规则会集体失效。代价是
`Disallow: /a%2Ab` 无法命中请求路径里的字面 `*`——这一条在 RFC 里是
SHOULD（见 §2），已列入未实现清单。

## 2. 明确未实现（不做承诺）

| 条款 | 要求 | 级别 | 状态与理由 |
| --- | --- | --- | --- |
| §2.2.2 字面 `*`/`$` | 匹配字面星号/美元符时双方用 `%` 编码 | SHOULD | **不实现**。需要给请求侧引入 ASCII 保留字符编码策略，会与现实中未编码的规则冲突（见 §1.2）。规则里的 `%2A` 只匹配请求里的 `%2A`。 |
| §2.3.1.2 重定向 | SHOULD 跟随至少 5 次连续重定向 | SHOULD | **不处理**。重定向由传输层（`moonbitlang/async/http`）自行跟随，本模块不解析重定向链，也不校验「5 次」上限。 |
| §2.4 缓存 | SHOULD 不超过 24 小时 | SHOULD | **不实现**。缓存仅在单次 `crawl` 调用内有效（每 origin 一次），不跨进程持久化。 |

> 结论：**§2.2 的匹配算法与 §2.3.1 的状态码语义已实现并逐条有测试**；
> 两处偏离（组选择、百分号编码向）已在 §1.1 / §1.2 单列，未覆盖的两项
> SHOULD（字面星号、重定向）与缓存时效见本节。

## 3. 状态码语义

| robots.txt 响应 | RFC 9309 | MoonCrawl 默认 | 可配置 |
| --- | --- | --- | --- |
| 2xx | 解析并执行 | 解析并执行 | — |
| 3xx | 跟随（≥5 次） | 交给传输层跟随；跟随后的 2xx 正文按规则解析 | — |
| 4xx | unavailable，可访问 | 放行，不产生规则 | — |
| 5xx | unreachable，完全禁止 | **禁止**，计入 `robots_unreachable` 与 `pages_skipped_unreachable` | `RobotsUnreachable::Allow` |
| 网络错误 | unreachable，完全禁止 | 同上 | 同上 |
| 解析失败 | 执行可解析部分 | 逐行容错 | — |

## 4. Crawl-delay

`Crawl-delay` **不是** RFC 9309 的内容，是广泛部署的扩展（Yandex 等支持）。
本项目把它当作附加约束：

- 解析为毫秒（支持小数，如 `1.5` → 1500ms）；
- 只用来**抬高**同 origin 的请求间隔，不会降低调用方设置的 `delay_ms`；
- 多个合并组都声明时取**最大值**（更保守）；
- 只取生效组的声明：最长 token 组没写 `Crawl-delay` 时不会回落到 `*` 组
  （与 §1.1 的组选择保持一致）。

## 5. 与主流实现的一致性

- 组选择与合并、最长匹配、等长 Allow 优先：与 Google 搜索中心的 robots.txt
  规范描述一致；与 RFC 字面的差异见 §1.1。
- 5xx 视为完全禁止：遵循 RFC 9309 §2.3.1.4 的 MUST；这与部分老爬虫
  「robots 取不到就放行」的旧惯例相反，属于有意选择，并在
  `RobotsUnreachable` 中保留显式退出口。
- 通配符匹配：线性双指针（单点回溯），与主流实现的匹配语义一致，
  且对 `a*a*a*…` 这类恶意模式没有指数复杂度。

## 6. 如何复核

```bash
moon test --target js -f "robots*"   # 22 个 robots 用例
moon test --target js -f "crawl*"    # 15 个引擎用例（含 4xx/5xx/不可达分支）
```
